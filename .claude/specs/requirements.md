# BidFlow 요구사항 원문 (2026-10-17 사용자 제공, 요약 없이 항목 보존)

> 프로젝트명 확정(2026-10-17): **BidMate**. 아래 원문의 "BidFlow"는 가칭이며 BidMate로 읽는다.

## 확정된 추가 결정 (2026-10-17)
- 네이버웍스 DOM 확인 방식: 확장에 DOM 진단 도구(probe)를 먼저 만들고, 사용자가 메일쓰기 화면에서 실행해 구조 리포트(JSON)를 프로젝트에 저장 → 그 리포트로 어댑터 구현.
- 네이버웍스 계정 도메인: @xcs.co.kr. 웹메일 호스트는 미확정 → 설정값으로 두고 기본 `mail.worksmobile.com`(가정).
- 개발 환경: macOS(개발), 대상 실행 환경은 Windows + 최신 Chrome. Node v22, npm 10.

## 1. 개요
프로젝트명: BidFlow(가칭). 트래커봇(TrackerBot)과 나라장터에서 확인한 입찰공고를 클릭 한 번으로 수집 → 상세정보/첨부파일을 PC 로컬 폴더에 저장 → 사전 등록 수신자에게 보낼 네이버웍스 메일을 자동 작성하는 Chrome 확장. 최종 검수/발송은 반드시 사용자 수동.

핵심 목표: 사용자 개입 최소화 / 트래커봇/나라장터 소스 수정 금지 / 백엔드 서버/클라우드 DB 없음 / Google Apps Script 미사용 / 초기 버전 AI API 미사용 / 공고 정보/첨부는 PC 실제 로컬 폴더 저장 / 수집 데이터와 메일 템플릿 완전 분리 / 메일 자동 발송 금지 / 추출 오류/첨부 누락 확인 가능 설계.

## 2. 기술 스택
React, TypeScript, Vite, Tailwind CSS, Lucide Icons. Chrome MV3(Content Scripts, Background Service Worker, Tabs, Downloads, Side Panel). 나라장터 OpenAPI, 상세화면 HTML DOM 파싱, Fetch. File System Access API, Downloads API, JSON 데이터 관리. 문서 파싱: PDF(PDF.js 등), HWPX(ZIP/XML), DOCX(XML), XLSX/XLSM(SheetJS 등), HWP(브라우저 호환 파서 검토), ZIP 해제. MV3 CSP/번들링 조건에 맞춰 선정, 외부 CDN 런타임 코드 실행 금지. 구형 HWP/스캔 PDF 제약 시 로컬 보조 프로그램 도입 여부 별도 검토.

## 3. 업무 프로세스
STEP 1 공고 선택 — A. 트래커봇: 목록에서 나라장터 바로가기 링크 탐색, 각 행에 [공고 수집] 버튼 삽입, 클릭 시 나라장터 공고 URL 식별, 원본 페이지/서버 수정 안 함. B. 나라장터: 공고 상세화면 인식 후 [공고 수집] 버튼 표시. 두 방식은 동일 수집 엔진 사용.

STEP 2 기본정보 수집(OpenAPI + 상세 HTML)
- 기본정보: 공고번호, 공고 차수, 공고명, 게시일시, 공고 구분, 발주기관, 수요기관, 사업금액, 추정가격, 사업기간, 계약방법, 낙찰자 결정방법, 예가방법, 공동수급 허용 여부, 입찰 참가자격
- 일정: 참가자격 등록마감, 입찰서 제출 시작/마감일시, 제안서 제출 기간, 제안서 평가일시, 개찰일시
- 평가: 평가방법, 차등점수제 적용 여부, 대외신인도 평가 및 배점, 수행실적 평가 및 배점, 실적 인정기간, 실적 인정금액, 실적 인정대상 및 조건
- 기타: 공고 원문 URL, 첨부파일 목록, 정정공고 여부, 수집일시
- 원칙: 공식 API 우선 → 없으면 상세 HTML → 그래도 없으면 첨부문서. 추출 못한 정보 임의 생성 금지, `확인 필요` 표시, 필드별 출처/원문 근거 기록, 공고번호+차수로 식별/중복 관리. API 실제 응답 필드 확인 후 매핑, 미제공 필드 가정 금지.

## 4. 첨부파일 전체 다운로드
목록 자동 추출, 공고별 로컬 폴더 자동 생성, 원본 파일명 유지, 동일 파일명 충돌 방지, 진행률 표시, 파일별 성공/실패 상태, 실패 재시도, 크기 검증, 원본 목록 vs 저장 목록 비교, 누락 시 경고. 인증 세션/특수 다운로드 요청은 실제 동작 분석해 처리. 접근 권한/보안 정책 우회 금지.

로컬 저장 구조:
```
<사용자 선택 루트>\
├── config\ settings.json, recipients.json, groups.json, templates.json
├── notices\2026\R26BK00000000_사업명\ notice.json, extraction.json, attachments\(원본 파일들)
└── index.json
```
설정 화면에서 루트 폴더 직접 선택. File System Access API 권한 승인/유지/재승인 구현. Downloads API로 임의 절대경로 저장 가능하다고 가정하지 않음. 브라우저 저장소에는 권한 핸들/최소 상태만, 원본 데이터는 PC 파일시스템.

## 5. 첨부문서 파싱/평가정보 추출
AI API 미사용. 파서+키워드+정규식+표 구조 분석. 문서명/형식 기준 우선순위: 1 제안서 평가기준/정량평가표, 2 입찰공고문, 3 제안요청서, 4 기타.
키워드: 대외신인도, 신인도, 수행실적, 실적평가, 유사사업, 정량평가, 배점, 실적 인정기간, 실적 인정금액, 차등점수제.
절차: 텍스트/표 추출 → 키워드 검색 → 주변 문단/표 추출 → 평가항목-배점 연결 확인 → 실적 인정조건 추출 → 복수 후보/모호하면 자동 확정 안 함 → 원문 근거 저장.
결과 예시(가상):
```json
{"credibilityEvaluation":{"score":4,"status":"verified","sourceFile":"평가기준.pdf","page":15,"evidence":"대외신인도 평가 4점"},
 "performanceEvaluation":{"score":6,"period":"최근 5년","minimumAmount":500000000,"status":"verified","sourceFile":"제안요청서.pdf","page":18,"evidence":"최근 5년 이내 유사사업 수행실적"}}
```
실패(PDF 추출 실패, HWP 미지원, 스캔 문서, 표 구조 불명확, 상충 정보) 시 `확인 필요` + 원본 파일 열기 제공. 평가정보 사용자 수정 가능.

## 6. UI/UX
Modern SaaS, Linear/Notion 계열 미니멀, 밝은 배경, 절제된 블루 포인트, 상태색 그린/오렌지/레드, 모달 최소화, 클릭 수 최소화, 부드러운 전환, 아이콘/상태정보 우선.
수집 인터랙션: 1) 버튼 클릭 즉시 시작(확인 모달 없음) 2) 사이트 우하단 플로팅 패널: 공고명, 현재 작업, 진행률, 다운로드 완료 파일 수, 오류 여부(예: 공고정보 조회 중 / 첨부파일 다운로드 중 (3/7) / 평가정보 추출 중 / 메일 작성 준비 중). 진행률은 실제 완료 상태 기반 3) 완료 시 작은 알림만, 누락/필수정보 실패는 확인 가능하게 4) 필수 작업 성공 시 네이버웍스 메일 작성 화면으로 이동, 오류 있으면 검수 화면 확인 후 진행.

## 7. 수신자/그룹 관리
수신자: 이름, 이메일, 부서, 메모, 사용 여부, TO/CC 구분, CRUD.
그룹: 생성/이름 수정/삭제, 그룹별 담당자 지정, 한 담당자 복수 그룹 허용, 기본 수신 그룹 지정, 공고별 수신 그룹 변경, 중복 이메일 제거. 예: 사업팀, 개발팀, 인프라팀, 전체 담당자. 메일 작성 시 기본값 적용하되 변경 가능. 로컬 설정 파일에 저장.

## 8. 메일 템플릿
제목/본문 수정, 공고정보 항목 선택/순서 변경/표시 여부, 필드 변수 삽입, 미리보기, 복수 템플릿, 기본 템플릿 설정.
변수 예: {공고명} {공고번호} {발주기관} {사업금액} {입찰마감일} {제안서평가일} {공동수급} {평가방법} {대외신인도} {실적평가} {공고URL}. 수집된 필드는 자유 사용. 새 필드는 필드 매핑 설정으로 추가 가능하되 소스에 없는 정보를 설정만으로 추출 가능하다고 가정하지 않음.
기본 양식 — 제목: `[입찰공고 공유] {공고명}` / 본문: 인사 → 1. 공고 개요(기관명, 사업명, 공고 게시일, 사업금액, 사업기간) → 2. 입찰 일정(참가자격 등록마감, 제안서 제출 기간, 제안서 평가일시) → 3. 계약 및 평가(계약방법, 평가방법, 차등점수제, 대외신인도 평가, 수행실적 평가, 실적 인정조건, 공동수급, 예가방법) → 4. 관련 자료(나라장터 공고 URL, 첨부파일 목록) → "검토 부탁드립니다."

## 9. 네이버웍스 메일 자동 작성 (최우선 기술 검증)
PC 크롬 웹 사용. 자동 입력: TO, CC, 제목, HTML 본문, 첨부파일 전체.
요구: 로그인 세션 활용 / 작성 화면 자동 열기 / 수신자 자동 입력 / 템플릿 매핑 / HTML 본문 / 첨부 자동 추가 / 업로드 완료 확인 / 작성 상태 유지 / 최종 검수는 사용자 / 전송 버튼 절대 자동 클릭 금지.
검증 대상 DOM: 수신자 입력 컴포넌트, 자동완성/이메일 확정, 제목 필드, 리치텍스트 편집기, 파일 첨부 컴포넌트, 업로드 완료 상태, 임시저장. 이벤트 발생만으로 성공 처리하지 않고 실제 화면 값/업로드 완료 상태 확인. 불가능한 기능은 실패를 숨기지 않고 원인/대체 방식 제시. 메일 API 즉시 발송 사용 금지.

## 14. 개발 우선순위
